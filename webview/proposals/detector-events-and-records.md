# 仕様案: 判定器のイベント通知と、演算結果の CSV 保存(bridgeApi 1 への追加)

状態: **案・方針は確定**(2026-10-03。§7)。確定したら英語にして `webview/BRIDGE.md` へ移し、このファイルは消す。
実装の順: ① 高機能版のページ(python-processing-core `js/viewer/advanced/`)→ ② Android → (Mac・Windows は後日)。

## 0. 目的

1. 判定器で起きたイベント(例: 立った・座った)をアプリが受け取り、**アプリの通知**を出す。画面オフ・裏でも出す。
2. 判定器の演算結果をアプリが逐次受け取って溜め、**計測が終わったらデータ CSV と一緒に保存する**(共有シートにも載せる)。

どちらも**拡張の仕組み**として入れる。全判定器に付けるのではなく、判定器ごとに「通知を出す」「CSV に残せる」を宣言したものだけが使う。
最初はサンプルとして、**通知 = 立ち座り、CSV = 高さ・速度(HVE。5 Hz に間引く)** の 1 つずつだけを実装する(本人、2026-10-03)。

## 1. 方針

- **アプリは判定器の中身を知らない。** 何を通知するか・CSV に何列書くかはページが決め、アプリは汎用の受け口
  (「通知を出す」「表へ行を足す」)だけを持つ。判定器を足しても、アプリは直さずに済む。
- **ライブ計測の間だけ受け付ける。** CSV 再生の解析中に届いたものは捨てる(再生は頭から解析し直すことがあり、通知が大量に出るため)。
- **追加のみ・後方互換。** bridgeApi は 1 のまま。対応していないアプリは知らない `kind` を読み捨てる(今の 3 アプリとも、ログに出して捨てる)。
- 画面オフ中の動作は、前回入れた `runInBackground` が前提(高機能版は付いている)。

## 2. アプリ → ページ: 使える機能を知らせる

`start(cond)` に `features` を足す。

| キー | 例 | 意味 |
| :--- | :--- | :--- |
| `features` | `["notify", "records"]` | このアプリが受け付けるページ → アプリの追加メッセージ。無い・空なら未対応 |

ページは `features` を見て、設定の「Notify」「CSV」のチェックを使えるようにするかを決める(未対応のアプリではそのチェックを灰色にして「このアプリでは使えません」と添え、送らない)。

## 3. ページ → アプリ: 通知

```json
{"kind": "notify", "tag": "posture", "title": "Stood up", "text": "score 82", "i": 123456}
```

| キー | 必須 | 内容 |
| :--- | :--- | :--- |
| `tag` | ○ | 通知のまとまり。`^[a-z][a-z0-9_]{0,31}$`。**同じ `tag` は 1 件に上書き**(通知欄が埋まらないように。上書きでも毎回鳴る) |
| `title` | ○ | 1 行目。64 文字まで、制御文字なし |
| `text` | | 2 行目。200 文字まで、制御文字なし |
| `i` | | イベントのサンプル番号(データ CSV の NUM)。アプリは通知の時刻表示に使う |

アプリ(Android)の扱い:

- 通知チャンネル「Detector events」(重要度: 既定。音・バイブは OS の設定に従う)を新しく作る。計測中の常駐通知(重要度: 低)とは別。
- 通知をタップするとアプリを開く。
- 同じ `tag` は 2 秒に 1 件まで(超えたぶんは最後の 1 件だけ、2 秒後に出す)。`tag` の種類は 1 計測 16 まで。
- 通知の権限が無いときは出さない(計測は続ける)。権限は今も起動時に求めている(`POST_NOTIFICATIONS`)。

## 4. ページ → アプリ: 演算結果の表(CSV)

ページは計測ごとに「表」を宣言し、行を足していく。アプリは表 1 つを CSV 1 本にする。

```json
{"kind": "table", "name": "hve", "columns": ["HEIGHT_CM", "VELOCITY_CM_S"], "title": "Height / velocity (5 Hz)"}
{"kind": "records", "name": "hve", "rows": [[123460, 12.3, -0.8], [123480, 12.1, -1.0]]}
```

| メッセージ | キー | 内容 |
| :--- | :--- | :--- |
| `table` | `name` | `^[a-z][a-z0-9_]{0,31}$`。`disconnect` は使えない(切断ログと名前がぶつかる) |
| | `columns` | 列名。`^[A-Z][A-Z0-9_]{0,31}$`、1〜32 列。`NUM` `DATE` は使えない(アプリが付ける) |
| | `title` | 任意。CSV の前書きに書く(64 文字まで) |
| `records` | `name` | 宣言済みの表 |
| | `rows` | `[[i, v1, v2, …], …]`。`i` = その行のサンプル番号(データ CSV の NUM)。値は `columns` の並びで、数・文字列・`null`(空欄) |

- **`start` の後に宣言し直す。** 宣言は計測ごと(`start` を受けたら前の宣言は消えたものとする)。レンダラが落ちて読み込み直したとき
  (アプリは `start` を送り直す)も同じ `name` ・同じ `columns` で宣言し直せば、**同じファイルへ続けて書く**。`columns` が違えば
  その表の行は捨ててログに出す。
- **送る頻度は 1 秒に 1 回程度にまとめる**(1 メッセージ 64 KB まで。今の受け口の上限)。
- 文字列の値: 64 文字まで。`,` と改行は空白に替える。`=` `+` `-` `@` で始まるもの(表計算ソフトが数式として読む)は空欄にする
  (アーティファクトと同じ規則)。数は JSON の数のまま書く(`-1.5` は数なので問題ない)。
- 行は届いた順に書く。判定器は遅れて確定するものがあるので、**NUM の順に並んでいるとは限らない**(要るなら読む側で並べ替える)。
- 表は 1 計測 16 まで。

アプリ(Android)の扱い:

- ファイル名はデータ CSV と同じベース名 + `_<name>`、同じフォルダ(Downloads/ESR Logger)、圧縮の設定も同じ
  (例: `6EAD12345678_20261003012345_hve.csv.gz`)。**最初の行が届いたときに作る**(行が 0 の表はファイルを作らない)。
- データ CSV と同じく 100 行ごとに追記する(途中でアプリが落ちても、そこまでは残る)。計測を止めたら残りを書いて閉じる。
- **DATE 列はアプリが付ける**: データ CSV の同じ NUM の行の DATE(UTC。データ CSV と同じ書式)。直近 30 分の NUM → DATE を覚えておき、
  それより古い・見つからない NUM は空欄。
- 共有シート(計測完了時に共有を開く)には、データ CSV と一緒にこれらの CSV も渡す。

CSV の形(データ CSV に合わせて、前書きは `//`、列名の行も `//` で始める):

```text
// Detector output  : hve (Height / velocity (5 Hz))
// Page  : Advanced 0.1.0 (10-03 09:53)
// Data file  : 6EAD12345678_20261003012345.csv.gz
//
//NUM,DATE,HEIGHT_CM,VELOCITY_CM_S
123460,2026/10/03 01:23:45.678,12.3,-0.8
```

## 5. ページ(高機能版): 判定器ごとの宣言と設定画面

判定器の一覧(`detectors.js` の `DETECTORS`)の各行に、使える機能を宣言する。宣言の無い判定器は今までどおり(通知も CSV も無し)。

```js
{ key: "hve", label: "Height / velocity — vertical moves, elevator", csv: true },
{ key: "posture", label: "Sit / stand", notify: true },
```

「Detectors to run」のモーダルの各行に、宣言に応じてチェックを足す。**宣言の無い行にはそのチェック自体を出さない。**

| 判定器 | Run | Notify | CSV |
| :--- | :---: | :---: | :---: |
| Height / velocity — vertical moves, elevator | ☑ | | ☐ |
| Sit / stand | ☑ | ☐ | |
| (宣言の無い判定器) | ☑ | | |

- **`notify: true`** の判定器: 「Notify」のチェック(**既定はオフ**)。オンのとき、その判定器のイベントを通知する。
- **`csv: true`** の判定器: 「CSV」のチェック(**既定はオフ**)。オンのとき、その判定器の表を CSV に残す。
- 共通:
  - Run を外した行は Notify・CSV も押せない(選んだ値は覚えておく)。
  - 選んだものはブラウザに覚える(今の `advanced.detectors` と同じく `localStorage`。キーは `advanced.notify` / `advanced.csv`)。
  - ライブ中に入れたり外したりしたら、そのときから出す/書く(CSV のファイルは計測ごとに 1 本のまま)。

最初に宣言するのはこの 2 つだけ:

| 判定器(キー) | 宣言 | 内容 |
| :--- | :--- | :--- |
| hve | `csv: true` | 表 `hve`、列 `HEIGHT_CM, VELOCITY_CM_S`(NUM・DATE の後)。series の `h` / `v` を **5 Hz に間引く**(20 行に 1 行。NUM が 20 の倍数の行) |
| posture | `notify: true` | `tag` = `posture`、`title` = `Stood up` / `Sat down`、`text` = `score 82`。立ち座りを確定したとき |

判定器の秒 → サンプル番号は、表示の秒 × cps = 行、`store.iOfRow(行)` = i(engine.js の `TIME` / `SHIFT` の後の値)。
ほかの判定器に足すときは、`DETECTORS` の宣言と、その判定器の表の列・通知の文面を足すだけで済むようにする。

## 6. 確かめ方

- 高機能版: ブラウザで `?dev` を付けて開く(`make_zip.py --serve` → `http://127.0.0.1:8791/?dev`)。`common/dev.js` が**アプリの受け口を
  真似る**(用意済み、2026-10-03):
  - 「Start simulated measurement」で `start` に `features: ["notify", "records"]` を入れる(「App features」を外すと未対応のアプリの真似)。
  - 届いた `notify` / `table` / `records` を §3・§4 の規則で検査し、パネルに出す(通知の最後の 5 件・表ごとの行数・規則に合わないものの警告)。
    同じ `tag` の 2 秒に 1 件・ライブの間だけ受ける、も同じ。
  - Stop の後「Download tables」で、表をアプリが書くのと同じ形の CSV に落とせる(DATE は開始時刻と cps から作った近似)。
  - 中身は `window.jmasDevApp`(`notices` / `tables` / `warnings`)から見られる(ヘッドレスのブラウザで確かめるとき)。
  - `common/bridge.js` の `post` は、アプリの外では `window.jmasDevSink` があればそれにも渡す(dev.js が置く。アプリの中では何もしない)。
- 判定器の出力が変わっていないことは `web_digest` で確かめる(送る処理を足すだけなので)。
- Android: 自己テスト `autotest_live` に、表の CSV ができたこと・行数が 0 でないこと・NUM がデータ CSV の範囲に入っていること・
  通知を受けた回数を足す。画面オフ(`--ez autotest_bg true`)の間も通知と行が届くこと。

## 7. 決まったこと(本人、2026-10-03)

1. 通知は判定器ごとに宣言し(`notify: true`)、宣言した判定器にだけ設定の「Notify」のチェックを出す(既定オフ)。最初は立ち座りだけ。
2. CSV も同じく判定器ごとに宣言し(`csv: true`)、宣言した判定器にだけ「CSV」のチェックを出す(既定オフ)。最初は HVE の高さ・速度を 5 Hz に間引いたものだけ。
3. 表の CSV はデータ CSV と同じ書き方(前書きも列名の行も `//` で始める)。
4. 通知も CSV もライブ計測だけ(再生の解析では出さない・作らない)。
